Память агента: Memory, CLAUDE.md, AGENTS.md, handoff

О чём. Между сессиями агент (Claude Code, Codex, Cursor) не «помнит как человек». Он снова читает то, что лежит в конкретных файлах и hooks — или то, что Memory продукта сам утащил. Если правило было только вчерашними словами в чате, в новой сессии его нет.

Куда. В твою ежедневную работу с агентами: package manager, тесты, решения спринта, стиль PR. То, что ты уже гоняешь в Claude Code / Codex / Cursor.

Зачем. Чтобы не повторять одно и то же в каждом новом чате; чтобы после compaction не терять решение; чтобы команда видела одну формулировку в CLAUDE.md / AGENTS.md в git, а не «я же сказал в чате».

Цель

Ты сможешь: выбрать, куда класть правило или состояние работы — Memory продукта, project CLAUDE.md / AGENTS.md, global ~/.claude/CLAUDE.md / ~/.codex/AGENTS.md, CLAUDE.local.md, handoff-файл — и проверить это на живом артефакте в новом сеансе агента.

Как видно. В репо есть файл с именем (CLAUDE.md или AGENTS.md или HANDOFF.md); новая сессия без вчерашнего чата следует правилу; для Claude Code — /context показывает файл в Memory files (или hook SessionStart compact печатает handoff).

Сдал: живой md на диске + новая сессия цитирует/следует правилу без повторной речи в чате.

Не сдал: правило только фразой в старом чате или только «запомни» без md в репо.

Нельзя: говорить «положи в файл» без имени пути; путать product Memory с CLAUDE.md/AGENTS.md; считать compact безопасным без handoff или reinject.

Механизм своими словами

Четыре реальных места — с именами файлов, не «абстрактный файл».

1. Текущая сессия (окно контекста)

Пока сессия жива, агент видит то, что влезло в context window. Новый чат / конец сессии — этого окна нет. Compaction сжимает длинную историю: summary остаётся, детали (решение спринта, запрет) могут выпасть. Сказанное только словами в чате сюда не переживает.

2. Memory продукта

«Запомни…» в ChatGPT/Claude или auto memory в Claude Code. Ок для личных привычек («короче»). Плохо: формулировку часто пишет продукт; команда в git не видит; версий нет; может всплыть не то. Это не замена CLAUDE.md / AGENTS.md в репо.

3. Файлы инструкций, которые инструмент читает сам при старте

  • Claude Code project: ./CLAUDE.md или ./.claude/CLAUDE.md (в git, на команду).
  • Claude Code global: ~/.claude/CLAUDE.md (ты, все проекты).
  • Claude Code личное в репо: ./CLAUDE.local.md + .gitignore.
  • Команды Claude Code: /init (черновик), /memory (список/правка), /context (что реально загрузилось).
  • Codex: ~/.codex/AGENTS.override.md иначе ~/.codex/AGENTS.md; в проекте от корня вниз до cwd — в каждой папке override затем AGENTS.md; ближе к cwd сильнее; ~32 KiB суммарно по умолчанию.
  • Cursor: AGENTS.md в корне и nested; или .cursor/rules/*.mdc с frontmatter.

И CLAUDE.md, и auto memory грузятся в старте сессии как контекст, не как жёсткий ban. Жёстко запретить действие (rm -rf, push в main) — hook PreToolUse, не строка в md.

4. Handoff-файл

Часто HANDOFF.md. Снимок работы для следующей сессии / после compact: Goal, Done, Open, Decisions, Files touched, Next command. Не «вечная норма проекта», а где остановились.

Hooks (Claude Code), когда без них механизм врёт

  • SessionStart с matcher compact — после compaction stdout снова в контекст (перечитать HANDOFF.md).
  • PreCompact — до сжатия: дописать handoff / заархивировать transcript. Project-root CLAUDE.md после compact reinject с диска; nested — пока снова не зайдут в ту папку.

Одно предложение: новая сессия и compact продолжают диск (и проверенную Memory), а не вчерашний чат.

Сейчас сделаешь то же на своём репо — сначала разбор двух готовых примеров.

Кейс 1. «Всегда pnpm» сказал только в чате

Ситуация

В команде договорённость: зависимости только через pnpm. Ты сказал это Claude Code в длинной сессии. На следующий день новая сессия ставит пакеты через npm.

Диалог вчера (та же сессия)

Ты: Всегда используй pnpm, не npm и не yarn. lockfile — pnpm-lock.yaml.

Агент: Ок, дальше только pnpm. Сейчас поставлю @types/node через pnpm add -D @types/node.

В той сессии слушался.

Диалог сегодня (новая сессия, без файла)

Ты: Добавь eslint в проект.

Агент: Сделаю. Запускаю npm install -D eslint…

Правила «pnpm» в контексте нет. Агент не «забыл из вредности» — в новой сессии этого правила просто не было в контексте сессии.

Почему сломалось

Правило жило только в окне той сессии. Новая сессия = пустой стол. Product Memory ты не просил «запомни». В ./CLAUDE.md строки не было.

Какой файл

В корне репо ./CLAUDE.md (или ./.claude/CLAUDE.md — один из двух; оба валидны для project scope):

## Package manager
- Always use pnpm, never npm or yarn.
- Install: `pnpm add` / `pnpm add -D`. Scripts: `pnpm <script>`.

Проверка: новая сессия → /context → в Memory files должен быть твой CLAUDE.md. Либо /memory → открыть project CLAUDE.md и убедиться, что строка там.

Новый чат с опорой

Ты: Добавь eslint в проект.

Агент: В CLAUDE.md — только pnpm. Ставлю: pnpm add -D eslint.

Результат

Правило сработало, потому что лежит в git и грузится в каждую сессию. Коллега с тем же репо получит то же без твоего чата.

Кейс 2. Длинная сессия, compact съел решение спринта

Ситуация

Три часа рефакторинга auth. В середине решили: JWT в httpOnly cookie, не localStorage. Сессия ушла в auto-compact. Потом ты открыл новую сессию (или продолжил после compact) — агент снова предлагает localStorage и спрашивает «а как мы храним токен?».

Диалог до compact

Ты: Фиксируем: access token только в httpOnly cookie. localStorage для токена — запрещён. Refresh — отдельный endpoint /auth/refresh.

Агент: Принято. Перепишу AuthProvider: убираю запись в localStorage, ставлю cookie flags Secure + SameSite=Lax.

Работа шла. Context window заполнился → compact.

После compact / в новой сессии без handoff

Ты: Продолжай auth refactor с того места.

Агент: Ок. Предлагаю хранить JWT в localStorage и слать в заголовке Authorization — так проще для SPA. Подтверди?

Решение спринта исчезло из живого контекста. Summary мог написать «обсуждали auth», без жёсткой нормы про cookie.

Почему сломалось

  1. Решение было только в диалоге (только в диалоге).
  2. Compaction сжал историю — деталь могла выпасть.
  3. Project-root CLAUDE.md после compact перечитывается с диска, но туда ты решение не писал. Nested/path rules — только когда снова читают matching файлы.
  4. Handoff-файла не было. SessionStart на compact ничего не reinject-ил.

Какой файл + hook

./HANDOFF.md (или docs/HANDOFF.md — имя на вкус, главное одно и то же место):

## Goal
Auth refactor: JWT only via httpOnly cookie.

## Done
- Removed localStorage token writes in AuthProvider
- Cookie flags: Secure, SameSite=Lax

## Open
- /auth/refresh endpoint + rotate on 401
- E2E: login → refresh → logout

## Decisions
- Token NEVER in localStorage or JS-readable storage
- Refresh: POST /auth/refresh, httpOnly cookie

## Files touched
- src/auth/AuthProvider.tsx
- src/auth/api.ts

## Next command
pnpm test src/auth && continue refresh endpoint

И в .claude/settings.json (проект) — reinject после compact:

{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "compact",
        "hooks": [
          {
            "type": "command",
            "command": "echo '=== HANDOFF ==='; cat \"${CLAUDE_PROJECT_DIR}/HANDOFF.md\" 2>/dev/null || echo 'No HANDOFF.md'"
          }
        ]
      }
    ],
    "PreCompact": [
      {
        "matcher": "auto|manual",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'Before compact: ensure HANDOFF.md has Goal/Done/Open/Decisions/Files/Next' >&2"
          }
        ]
      }
    ]
  }
}

(PreCompact: matcher manual или auto — по тому, что сработало; можно без узкого matcher, если хочешь на любой compact. Смысл — напомнить/дописать handoff до сжатия.)

Дополнительно одну строку решения можно продублировать в ./CLAUDE.md, если это уже норма проекта на месяцы, не только на этот спринт.

Новая сессия с опорой

Ты: Продолжай по HANDOFF.md.

Агент: По HANDOFF: токен только httpOnly cookie, localStorage запрещён. Open — /auth/refresh и E2E. Дальше endpoint refresh…

Результат

Следующая сессия не переспрашивает архитектуру. Compact не стирает решение, потому что оно на диске и после compact снова влетает через SessionStart compact (stdout → контекст). Project-root CLAUDE.md и так reinject с диска — но handoff несёт состояние работы, а не только вечные правила.

Когда Memory продукта ок: личные предпочтения; черновик, который ты готов править через UI памяти; не шарится с командой.

Когда Memory врёт / неконтролируем: «запомни» расплывчатое; продукт сам додумал; команде нужна одна строка в PR; нужна история изменений; после смены аккаунта/машины память пропала.

Когда нужен md в репо: shared, точная формулировка, versioned, review в PR, одинаково у всех агентов на стенде.

Что пишут вендоры

Чтение 20.09.2026. После механизма — опоры, не вместо него. Замера задачи «файл vs чат» на живых страницах нет — цифрой урок не подменяю.

Claude Code — memory / CLAUDE.md

Memory · то же по claude-md

CLAUDE.md пишешь ты; auto memory пишет Claude. Оба грузятся в старте сессии; это context, не enforced config. Жёсткий блок — PreToolUse. Пути: project ./CLAUDE.md или ./.claude/CLAUDE.md; user ~/.claude/CLAUDE.md; local CLAUDE.local.md (gitignore). /memory, /context, /init.

Context window / compaction

Context window

После compact: project-root CLAUDE.md и unscoped rules — reinject с диска; auto memory — с диска; nested CLAUDE.md и rules с paths: — снова, когда агент читает matching файлы; SessionStart с source compact — stdout хука снова в контекст.

Hooks

Hooks reference · Hooks guide

SessionStart matcher включает compact (reinject после сжатия). PreCompact — до compaction (manual / auto). Guide прямо показывает пример «Re-inject context after compaction» через SessionStart + compact.

Codex — AGENTS.md

Custom instructions with AGENTS.md

Глобально: ~/.codex/AGENTS.override.md иначе AGENTS.md. Проект: от корня вниз до cwd, в каждой директории override затем AGENTS.md; ближе = later = сильнее; default cap ~32 KiB (project_doc_max_bytes) — лимит продукта, не замер урока.

Cursor — rules / AGENTS.md

Rules

AGENTS.md в корне и nested; альтернатива — .cursor/rules/*.mdc с frontmatter. Plain .md в .cursor/rules без frontmatter система rules игнорирует.

Граница

Урок не про: навыки/skills как пакеты процедур; MCP; полный каталог всех hook events; org-managed CLAUDE.md через MDM; «научить модель помнить без файлов». Не обещает 100% следование строке в md — это context.

Практика

Один свой репо, где ты реально гоняешь Claude Code, Codex или Cursor. Примерно 15 минут.

1. В одном своём репо открой или создай ./CLAUDE.md (или ./.claude/CLAUDE.md). Одна конкретная норма команды (пакетный менеджер, тест-команда, ветка). Если основной инструмент Codex/Cursor — ту же норму можно сразу в корневой AGENTS.md.

Сдал: файл на диске + в новой сессии агент следует норме без повторной речи «помни, я говорил»; для Claude Code /context показывает файл в Memory files.

Не сдал: правило только в чате или только «запомни» без файла в репо.

2. Рядом заведи HANDOFF.md с шестью блоками: Goal, Done, Open, Decisions, Files touched, Next command. Заполни по реальной текущей задаче (можно коротко).

Сдал: все шесть заголовков есть, Next command — одна копируемая команда.

Не сдал: простыня «вчера много сделали» без Open/Next.

3. (Claude Code) Добавь SessionStart hook с matcher compact, который печатает содержимое HANDOFF.md в stdout. Опционально PreCompact — напоминание дописать handoff.

Сдал: запись в .claude/settings.json (или user settings), /hooks видит SessionStart.

Не сдал: «потом руками вставлю» без hook.

Пропустил: основной инструмент Codex/Cursor — шаг 1 на AGENTS.md обязателен, шаг 3 можно пропустить.

4. Если основной инструмент — Codex или Cursor: положи ту же командную норму в AGENTS.md (корень; для Cursor можно nested). Для Codex проверь, что нет мешающего AGENTS.override.md не там.

Сдал: агент в новом запуске цитирует правило без твоей повторной речи в чате.

Не сдал: правило только в UI Memory продукта.

Нельзя: оставлять командное правило только фразой в чате; путать product Memory с CLAUDE.md/AGENTS.md; писать «положи в файл» без имени пути; считать compact безопасным без handoff или reinject; ждать, что md = жёсткий ban (для ban — PreToolUse).
