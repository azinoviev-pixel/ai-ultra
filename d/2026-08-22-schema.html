Структурированный вывод по схеме вместо «ответь в JSON»

После этой страницы ты на одном выдуманном вечере пишешь схему ответа (поля и типы) и бракуешь одну фразу, которая выглядит как JSON, но схему ломает. нельзя: просить ответь в JSON без схемы.

Зачем это сейчас

Вечер записи в поликлинике «Северная». Бот должен ответить коду: можно ли слот в воскресенье после 19:00.

Кто-то пишет «ответь в JSON». Приходит {"ok":"да","slot":19:00}. Выглядит как JSON. Схему ломает: ok это строка, slot без кавычек, поля reason нет.

Эта страница не про кэш, не про окно, не про роли, не про «больше контекста».

Как это устроено

Структурированный вывод (structured outputs): API берёт схему (schema) полей и типов. Модель должна её держать.

У OpenAI схема живёт в response_format / text.format [1]. JSON mode даёт валидный JSON, схему не держит [1]. «only Structured Outputs ensure schema adherence» [1]. Когда можно, бери Structured Outputs, не JSON mode [1].

Chat Completions: response_format type json_schema, strict true [1]. В схеме: required и additionalProperties false [1]. Function calling для инструментов. response_format для ответа человеку [1].

6 августа 2024 запустили Structured Outputs: ответ держит схему, которую задал разработчик [2]. Сильно формулировать промпт, чтобы поймать формат, больше не нужно [1].

У Anthropic два рубильника. Ответ по схеме: output_config.format [3]. Аргументы инструмента: strict true [3]. Не фраза «ответь в JSON» [3].

Ответ держит схему через constrained decoding [3]. В схеме: required и additionalProperties false [3]. output_format переехал в output_config.format. Beta header больше не нужен [3].

JSON outputs: что Claude говорит. Strict tool use: как он вызывает функции [3].

У Gemini схема в response_format, mime_type application/json [4]. Last updated 2026-08-17 UTC. Structured Outputs: формат финального ответа. Function Calling: действие по ходу разговора [4]. «always validate values in your application» [4]. Стенд Probe здесь не брал. Чисел нет.

Как это садится на твою работу

Репозиторий не открываем.

Тот же вечер поликлиники. Схема ответа: ok boolean, slot string или null, reason string.

Фразу, которая выглядит как JSON, но ломает типы, обязательные поля или тащит лишнее, бракуешь.

Проверка на провал. Если написал только «ответь в JSON», правила нет.

Кто так уже делает

OpenAI, запуск 6 августа 2024. gpt-4o-2024-08-06 со Structured Outputs: 100% на их оценке сложных JSON Schema. gpt-4-0613: меньше 40% [5]. В таблице рядом: Prompting Alone / Structured Outputs (strict=false) / Structured Outputs (strict=true) [5]. Их стенд, август 2024. Не твоя схема сегодня. На Claude и Gemini эти проценты не переносить.

Живой гайд, чтение 22.08.2026. Таблица «Adheres to schema»: Structured Outputs Yes, JSON Mode No [1].

Anthropic, лимиты компиляции, чтение 22.08.2026. 20 строгих инструментов на запрос. 24 необязательных параметра суммарно по всем строгим схемам и JSON-выводу. 16 параметров с union (anyOf или type string|null) [3]. Четыре строгих инструмента по 6 необязательных полей уже упираются в 24 [3]. Схема, которая проходит у GPT, здесь может дать 400 «Schema is too complex for compilation» [3]. 20 / 24 / 16 это их компилятор, не потолок OpenAI и не Gemini.

Неочевидные решения

Схему клади в поле API, не в фразу промпта. Цена: надо написать поля и типы. «ответь в JSON» это не схема [1].

Валидный JSON мало. Цена: {"ok":"да"} бракуешь, даже если парсится [1].

Два рубильника Anthropic делают разную работу. Цена: схему ответа не вешай на strict tool use [3].

Практика, 15 минут

Сцена. Вечер записи в поликлинике «Северная». Бот должен ответить коду: можно ли слот в воскресенье после 19:00.

Напиши схему ответа. Потом одну фразу, которая выглядит как JSON, но схему ломает. Эту фразу забракуй.

схема:
  поле: тип
  поле: тип
брак: { … }
почему брак: …
нельзя: просить ответь в JSON без схемы

Сверка (не единственный правильный текст, но такой проходит):

схема:
  ok: boolean
  slot: string или null
  reason: string
брак: {"ok": "да", "slot": 19:00, "note": "если врач свободен"}
почему брак: ok — строка, не boolean; slot без кавычек; поля reason нет; лишнее note
нельзя: просить ответь в JSON без схемы

Сдал, если есть поля и типы, один конкретный брак, и точная строка нельзя.

Не сдан, если написал только «ответь в JSON», разобрал кэш или окно, или снова «положи правило в файл».

нельзя: открывать и менять репозиторий.

Три вопроса

  1. Написали «ответь в JSON». Пришло {"ok": "да", "slot": 19:00}. Этого хватает?
  2. В схеме ok — boolean, reason — string, лишних полей нет. Пришло {"ok": true, "reason": "окно есть", "note": "если врач согласится"}. Пропускать или браковать?
  3. Второй вечер снова просят «ответь в JSON» и схемы нет. Что пишешь в строке нельзя?
Ответы
  1. Нет. Это похоже на JSON, схему ломает: ok — строка, slot без кавычек, поля reason нет.
  2. Браковать. Поля ok и reason на месте, но note схема не просит.
  3. нельзя: просить ответь в JSON без схемы
