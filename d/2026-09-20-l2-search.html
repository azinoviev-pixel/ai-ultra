Без источника не верю

О чём. Модель умеет отвечать из головы и умеет отвечать с опорой: веб-поиск или твои файлы. Без видимого источника свежий или узкий факт — это угадывание, даже если тон уверенный.

Куда. В любую работу, где ты спрашиваешь «что сейчас», «что в моём документе», «какая цифра в отчёте» — сам в чате или через агента с поиском и файлами.

Зачем. Иначе ты принимаешь уверенный абзац как проверку. Потом оказывается: cutoff, чужая дата, или модель «нашла» то, чего в файле нет. Правило одно: нет источника — не верю.

Два разных режима

Из головы. Модель продолжает по тому, чему её учили. Это нормально для черновика письма, плана, объяснения знакомой темы. Это слабо для новостей, цен, внутренних цифр, юридических формулировок «как в договоре».

С опорой. Модель ходит в поиск или в загруженные файлы и должна показать, откуда взяла кусок. Google в доке по Grounding with Google Search пишет: инструмент связывает Gemini с актуальным вебом, чтобы ответы были точнее и с проверяемыми источниками за пределами cutoff. В ответе приходят цитаты — аннотации, которые цепляют отрезок текста к URL.

Источник: Grounding with Google Search — Gemini API (чтение 20.09.2026; Last updated 2026-09-17 UTC).

OpenAI в Responses API даёт tool file_search: модель ищет по vector store с твоими файлами и возвращает ответ вместе с file citations (какой файл). Можно запросить и сами search results кусков.

Источник: File search — OpenAI API (чтение 20.09.2026).

Anthropic в Citations и Files API позволяет включить цитаты по загруженному документу: ответ ссылается на предложения или страницы источника, а не только «я прочитал файл».

Источник: Citations — Claude · Files API (чтение 20.09.2026).

Сильный ход не «включить все тумблеры». Сильный ход — заранее решить: этот вопрос из головы или с опорой. И проверить, что опора реально видна.

Что ломается, когда «поискали»

Уверенный тон без ссылки. Модель пишет «по последним данным» и не даёт URL или файла. Для свежего факта это брак.

Ссылка есть, куска нет. Особенно с файлами: citation указывает на файл, а не на конкретный абзац. В обсуждениях вокруг Responses API люди упираются в то, что annotation часто даёт file_id и место вставки, а не готовый «этот chunk = эта фраза». Практический вывод: открывай источник и читай глазами то место, на которое опираешься.

Источник-фон для осторожности: cookbook OpenAI по file search в Responses API показывает, как доставать search_results через include, если нужны сами куски — Doing RAG on PDFs using File Search (Mar 11, 2025; архивный cookbook — концепт; канон API — File search выше). Чтение 20.09.2026.

Поиск есть, а вопрос был про твой файл. Модель ушла в веб, хотя тебе нужна цифра из твоего PDF. Или наоборот. Если в запросе не сказал «только из приложенного файла / только с поиском», режим выбирает она.

Цитата на документ, которого ты не давал. Или «как в договоре» без страницы. Для Claude Citations как раз смысл в том, что утверждение цепляется к твоему источнику. Нет цитаты — утверждение из головы.

Как спрашивать, чтобы было что проверить

Один вопрос. Один режим.

Пример из головы (черновик): «Набросай короткое письмо клиенту про перенос встречи. Факты не выдумывай — дат и цен нет».

Пример с вебом: «Найди в открытых источниках, что официально сказано про X. В ответе — ссылка и одна цитата. Без ссылки не отвечай».

Пример со своим файлом: «Ответь только по приложенному PDF. Если в файле нет — скажи „в файле нет“. Дай цитату и где это в документе».

Если инструмент умеет citations / file_search / grounding — включи их под этот вопрос. Если в обычном чате нет тумблера — всё равно требуй: «покажи источник или скажи, что не знаешь».

Как принимать ответ за десять секунд

  1. Есть ли источник: URL, имя файла, страница, цитата?
  2. Открывается ли он? Совпадает ли кусок с тем, что написала модель?
  3. Режим тот? Спрашивал про свой файл — не должен уехать в общие рассуждения.
  4. Нет источника на свежий или узкий факт — не верю. Одна короткая правка: «без источника не принимаю — дай ссылку/цитату или скажи, что не нашёл».

Не спорь про тон. Смотри опору.

Умение

На один рабочий вопрос выбрать режим (из головы / веб / свой файл), потребовать видимый источник или честное «нет в источнике», и за короткое время принять или вернуть ответ по наличию проверяемой опоры.

Граница. Сегодня не уходи в сравнение «какой поиск умнее» и не строй с нуля свою базу эмбеддингов. Один вопрос. Одна опора. Одна проверка.

На этих опорах нет стенда с числом «насколько реже врёт ответ с источником». Ответ с цитатой на веб или на свой файл — другой ход, чем ответ из головы. Чужие квоты API и чужой процент из архивного cookbook не закон проверки твоего ответа.

Практика · пятнадцать минут

Возьми один реальный вопрос, где без источника нельзя. Например: свежий факт с сайта, цифра из своего документа, «что официально сказано» в публичной доке.

В чате с моделью (или с поиском и файлами, если они у тебя включены) задай этот один вопрос и явно потребуй: ссылка или цитата из файла; иначе «не знаю / в файле нет».

За короткое время проверь три вещи: источник есть, открывается, кусок совпадает.

Напиши себе одну строку: «принял — источник …» или «вернул — источника нет / кусок не совпал».

Если вернул — одна правка тем же правилом. Второй ответ снова проверь. На этом стоп. Не спорь про тон. Смотри опору.

Сдал, если есть один вопрос, явное требование источника, проверка трёх вещей и одна строка сдачи. Если был второй ответ — в строке видно, помогла ли правка.

Три вопроса

1. Модель отвечает уверенно, ссылки нет, факту нужна опора. Что пишешь?
Вернул: без источника не принимаю — дай ссылку или цитату, либо скажи «не знаю / в файле нет».
2. Ссылка открылась, но цифра в ответе и на странице разные. Принял или вернул?
Вернул — кусок не совпал. Одна правка: цитата должна совпасть со страницей.
3. Хочется сравнить три поиска «кто умнее» или задать пять вопросов за раз. Можно?
Нет. Сравнение поисков и пять вопросов сразу — провал. Один вопрос, одна опора, одна проверка.
