17.08 · Модель vs harness

Закрыто здесь, не домашка. Источник: karpathy/nanochat · runs/speedrun.sh.

Цепочка nanochat

  • data веса — шарды корпуса (nanochat.dataset, ~2B символов на токенизатор, ~170 шардов на pretrain)
  • tokenizer веса — tok_train, vocab 32768 на этих данных
  • train веса — base_train, чекпоинт d24 / GPT-2 grade
  • SFT веса — chat_sft, разговор и tool tokens
  • eval harness — base_eval / chat_eval, CORE и BPB, веса не пишет
  • serve harness — chat_cli, цикл inference, не новые веса

hole-fix · 5 мест, где жрутся токены

  1. Инструкции агента + промпт на каждый ход Runner.
  2. JSON-схемы трёх tools (read_file / run_cmd / write_file) в каждом запросе к модели.
  3. read_file кладёт весь файл в контекст (в success — calc.py и test_calc.py подряд).
  4. run_cmd возвращает весь stdout+stderr без обрезки.
  5. write_file гоняет полный текст файла туда-обратно; trace_include_sensitive_data=True пишет все I/O в трейс.

Падение = data / контекст / tool schema / inference / eval.
